# 原始教程修订说明

用户提供的教程适合作为学习路线，但其中部分操作不能直接成为本仓库的工程规范。

| 原教程做法 | 本仓库的决定 | 原因 |
| --- | --- | --- |
| 所有依赖使用 `@latest` | 固定 GoFrame 和基础设施版本 | 让环境可复现，升级可以单独评审 |
| 使用 `mysql:latest` | 使用 `mysql:8.4.11` | 防止镜像静默切换大版本 |
| 使用允许匿名访问的 Bitnami etcd 镜像 | 本地单节点使用官方 etcd 镜像 | 与上游运行文档保持一致 |
| 添加大量公共 Docker 镜像源 | 项目配置不修改 Docker 全局镜像源 | 镜像源的可信度和可用性属于机器或组织策略 |
| 应用使用 MySQL root 账号 | 创建本地 `shop` 应用账号 | 降低权限并分离管理账号与应用账号 |
| 提交或复制一份共享运行配置 | 提交 `config.yaml.example`，忽略 `config.yaml` | 避免本地和生产凭据进入 Git |
| DAO 查询失败时返回空结果 | 映射并返回错误 | 静默失败会给用户和 Agent 制造错误证据 |
| 将请求对象直接交给 DAO 插入 | 将校验后的应用层输入映射为持久化模型 | 防止传输层字段直接控制数据库写入 |
| 直接把 DAO Entity 作为 Protobuf 协议 | 维护独立 API 消息和映射 | 数据库结构和公共 API 的演进节奏不同 |
| 保存类似 MD5 的密码值和原始密保答案 | 使用自适应密码哈希，不保存可恢复的密保答案 | 满足当前认证安全基线 |
| 订单写入成功即视为支付成功 | 使用明确的支付状态机和幂等键 | 本地数据库提交不能证明外部支付成功 |
| 缺少 etcd 配置时 `panic` | 打警告并退回本地文件注册表 | 单个服务应能在没有 etcd 的情况下开发和测试 |
| JWT 密钥写死在源码里，HS256 共享密钥 | `user` 持有 Ed25519 私钥，其他进程只拿公钥；缺失时拒绝启动 | 写进源码等于公开密钥；共享密钥让每个验签方都能伪造令牌（任务 0004） |
| 网关 JWT 中间件按路由分组挂载 | 整个 `/frontend` 默认拒绝，只放行白名单路由；后端服务再验一次 | 忘记分组的新接口不会默认公开（任务 0004） |
| 列表不加条件、删除只按 `id`、直接插入请求对象 | 按调用者过滤和限定写入，只写白名单字段 | 原写法任何人都能看到、删除别人的数据（任务 0005） |
| 管理员密码使用双重 MD5，注册接口公开 | Argon2id（与 user 共用 `utility/password.go`）；没有公开注册，第一个超级管理员由命令行创建 | MD5 可被批量暴力破解；公开注册等于任何人都能进后台（任务 0006） |
| 七牛 AccessKey/SecretKey 写在教程和配置文件里 | 只用自己账号的凭据，放在被忽略的配置或环境变量里；默认使用本地存储 | 教程里的凭据属于别人；写进仓库就等于公开 |
| 上传信任文件名后缀，并把文件名拼进对象 key | 按内容判断类型，只允许常见图片格式，key 由服务端随机生成 | 防止上传可执行脚本的 HTML/SVG，以及路径、特殊字符问题 |
| gateway-admin 直连 `current` 库写入 `file_info` | 新建 file 服务持有 `file` 库 | 网关不持有数据库（任务 0006） |
| 商品列表、图片列表不加条件；`InsertAndGetId(req)`、`Update(req)` 直接写请求对象 | 只写白名单字段；图片随商品详情返回 | 原写法允许客户端写入销量等不该由它写的字段（任务 0007） |
| 分类 `level` 由客户端填写，示例数据层级混乱 | 由父分类推导，最多三级，不能移动，使用中的分类不能删除 | 保证分类树和商品上的分类链始终一致（任务 0007） |
| 商品表加 `images` JSON 列，图片表再冗余 URL | 只在 `goods_images` 冗余 URL，读性能交给 Redis 缓存 | 同一份数据存两处容易不一致（任务 0007） |
| `docker run redis`（latest），Redis 连不上时服务直接退出 | Compose 固定 `redis:7.4.2`，设密码、不持久化；Redis 故障时回退到 MySQL | 缓存故障不应变成服务故障（任务 0007） |
| 库存是 `goods_info.stock`，后台表单直接覆盖 | 独立的库存账本：预留、提交、释放，幂等、全有或全无；后台只能增减 | 防止超卖，防止后台修改覆盖进行中的订单（任务 0008） |
| `docker cp` IK 插件，`/sync/goods` 不需要鉴权，root 读 binlog，按列位置解析 | 构建时安装并校验 sha256；删除同步接口；只读账号；binlog 只做通知、按列名回查 | 可重复构建、最小权限、表结构变化时不会错位（任务 0009） |
| 订单金额和收货地址由客户端填写，下单不扣库存，前台订单列表可以按任意用户查询，售后直接写入 | 服务端算价、地址快照、预留库存、状态机与超时关单、按用户隔离、售后校验归属与支付状态 | 原写法可以随意改价、看到所有人的订单、超卖（任务 0010） |
| banner 直接填图片 URL 和商品名，链接只校验格式，可按 `sort=2` 倒序 | 用 `fileId` 引用文件、商品名从商品服务读取、链接只允许 http/https、固定升序 | 防止首页链接执行脚本，防止图片和名字被随意填写（任务 0011） |
| 没有支付环节，订单状态由接口直接改成"已支付" | 独立的支付模拟器进程和库；回调验签且只当提示、以查询结果为准；付款与关单用行锁裁定，晚到的付款自动退款；付款后才提交库存 | 外部支付会超时、重复回调、丢回调，回调地址谁都能调用（任务 0012） |
| 下单后起 goroutine 往 RabbitMQ 延迟交换机发超时消息 | 事件和订单在同一个事务里写进 outbox，由投递器发出并等待确认；延迟用普通持久队列 + TTL + 死信；消费方 Inbox 去重；数据库扫描保留作兜底 | 提交后、发送前崩溃会丢消息（详细设计 B1）；延迟插件只存在单个节点上（任务 0011 说明原因，任务 0013 实现） |
| 只在更新后删除缓存，创建后不处理；删除失败只记日志 | 创建、更新、删除、挂图、删图都删除缓存；删除失败后台重试 | 实测中出现了新商品被"不存在"标记挡住、Redis 恢复后旧数据仍被返回的问题（任务 0007） |
| 网关透传一个明文用户 ID 头作为身份 | `user` 服务签发 HS256 令牌并用拦截器验签，网关只转发 `Authorization` | 明文 ID 头任何人都能填写；身份必须由持有密钥的一方证明 |
| 直接信任 `go mod tidy` 之后的版本 | 显式锁定 GoFrame v2.10.2，并在 `tidy` 后用 `go list -m` 复核 | `tidy` 会为补全缺失依赖拉取最新版，实测把 gf 从 v2.10.2 降到 v2.9.0，触发 `tablewriter` API 不兼容的编译错误 |

## 暂缓实现的内容

原教程中的 CRUD 片段、JWT、etcd 注册和 gRPC 服务装配没有被直接复制，而是拆成了带测试和验收条件的独立任务：持久化与 etcd 见任务 0002，JWT 见任务 0003 和 0004，interaction 服务见任务 0005，admin、file 与 gateway-admin 见任务 0006，goods 商品服务与缓存见任务 0007，库存与上下架见任务 0008，搜索见任务 0009，订单见任务 0010，banner 见任务 0011，支付见任务 0012，RabbitMQ 事件见任务 0013。
