# 任务 0009：search 搜索服务（Elasticsearch + IK + binlog 同步）

状态：已完成。来源是原教程的 Elasticsearch、Kibana、IK 分词器和 search 服务章节。开发说明见 [`docs/development/search-service.md`](../docs/development/search-service.md)。

## 新增了什么

| 类别 | 内容 |
| --- | --- |
| 基础设施 | Compose 新增 `elasticsearch`：用 `deploy/elasticsearch/Dockerfile` 在 8.11.0 镜像里装好 IK 插件，插件下载锁定 sha256。`kibana` 放在 `tools` profile 里，默认不启动，界面为中文 |
| 账号 | `007_search_sync_user.sql`：`search_sync` 账号，只有 SELECT goods 库和读取 binlog 的权限 |
| 进程 | `app/search`（gRPC `:31006`）：不持有任何密钥，只有公开方法 |
| 前台 HTTP | `GET /frontend/search/goods`：支持关键词、分类、品牌、价格区间、5 种排序，结果带高亮 |
| 共享代码 | `utility.UnaryServerAuth(nil, ...)`：没有受保护方法的服务可以不配置公钥 |

## 与原教程的差异

| 原教程 | 本仓库 | 原因 |
| --- | --- | --- |
| `docker cp` 插件进容器，再进容器手动安装 | Dockerfile 构建时安装，锁定 sha256 | 可以重复构建；下载内容一旦变化，构建直接失败 |
| search 是直接对外的 HTTP 服务（:8499） | gRPC 服务，经 gateway-h5 公开 | 和其他服务一样走网关 |
| `POST /sync/goods`：不需要鉴权的写索引接口 | 删除 | 任何人都能往索引里写入任意商品 |
| 用 root 读 binlog | 专用的只读账号 `search_sync` | 最小权限 |
| binlog 从"当前位置"开始，启动前的数据和停机期间的变更都会丢 | 先记下位置，全量重建，再从记下的位置继续 | 重建期间发生的变更也会被补上 |
| 按列的位置解析行数据，表结构变了就会错位（教程自己也提醒了这一点） | binlog 只当作"某商品变了"的信号，再按列名查询 MySQL 的最新状态 | 重放、乱序、重复都会收敛到同一份文档；列被删除或改名时直接报错 |
| 同步失败只记日志 | 按退避间隔无限重试同一个商品，暂停消费，不丢弃 | 实测：ES 停掉期间改名的商品，在 ES 恢复后被补上 |
| 软删除靠查询时用 `wildcard deleted_at` 过滤 | 索引里只放上架且未删除的商品 | 查询更简单，也不会漏掉过滤条件 |
| 价格字段叫 `price`，`created_at` 转成字符串 | `price_cents`，日期按 date 类型索引 | 和商品服务保持一致 |
| 高亮直接用 `<em>` 拼接原文 | 高亮使用 `encoder: html` | 商品名里的 `<script>` 会被转义，前端可以直接当 HTML 插入，不会产生 XSS |
| `from + size` 不设限 | 限制 `page × size ≤ 10000` | 超过 ES 的结果窗口会报错，提前给出明确的参数错误 |
| 直接写固定的索引名 | 写入别名 `goods`，每次启动新建物理索引 `goods_<时间戳>`，再原子切换别名 | 重建期间搜索不中断；改映射只需要重建 |
| 映射允许动态字段 | `dynamic: strict` | 出现未知字段时报错，而不是让 ES 自己猜类型 |
| olivere/elastic v7 客户端 | 官方 go-elasticsearch v8 | olivere 已停止维护，并且对应的是 ES 7 |

## 已知局限

- 每次启动都全量重建索引。目前商品数量小，代价可以忽略；商品多了以后，应该改为持久化 binlog 位置，只在需要时才重建。
- 搜索结果比 MySQL 晚约 1 秒（binlog 延迟加上 ES 的刷新间隔）。库存和销量以商品详情为准。
- binlog 同步意外停止时，会记一条 ERROR 日志，之后索引不再更新，直到服务重启（重启会重建索引）。

## 验收标准

- 单元测试：参数校验（包括结果窗口）、查询结构（筛选条件不参与打分、排序有确定的兜底顺序、只设上限的价格区间）、按列名取商品 ID（图片表用 goods_id，不用图片自己的 ID）、同步时按当前状态决定写入还是删除、ES 故障时持续重试、服务停止时退出重试。
- 集成测试（真实 ES + IK，`GOFRAMESHOP_IT=1`）：
  - "电视"能命中"电视机""电视支架"；标签也能搜到。
  - 品牌、分类、价格筛选和三种排序都正确。
  - 名称里含 `<script>` 时高亮结果已转义。
  - 写入、删除（删除不存在的文档也不报错）、重建切换别名并删除旧索引都正确。
- 端到端：
  - 新商品默认下架、搜不到；上架约 2 秒后能搜到；提交订单后按销量排序排到第一；下架后从搜索结果里消失。
  - ES 停掉时搜索返回 `code:14`；ES 停掉期间改的商品名，恢复后能搜到。
