# 任务 0006：admin 服务、gateway-admin 与图片上传

状态：已完成。来源是原教程的"七牛云图片上传"和"图片上传接口存储"章节。教程把上传和数据库写入都放在 gateway-admin 里，并依赖之前标为"可以跳过"的 admin 服务；这里按本仓库的规则拆成三个进程。开发说明见 [`docs/development/admin-and-file.md`](../docs/development/admin-and-file.md)。

## 新增进程

| 进程 | 地址 | 库 | 职责 |
| --- | --- | --- | --- |
| `app/admin` | gRPC `:31003` | `admin` | 管理员登录、创建管理员；持有**管理员**密钥对的私钥 |
| `app/file` | gRPC `:31004` | `file` | 记录文件元数据（谁、何时、存在哪、URL）；不接触文件内容 |
| `app/gateway-admin` | HTTP `:8299` | 无 | 后台 HTTP 入口；校验图片并写入对象存储，再调用 file 服务记录 |

## 已采用的决定

| 决定 | 原因 |
| --- | --- |
| 管理员令牌使用独立的 Ed25519 密钥对，签发者为 `goframeshop-admin` | 商城用户令牌在后台被拒绝，反过来也一样；任何一个私钥泄露都不会波及另一套身份 |
| 没有公开的管理员注册接口；第一个超级管理员用 `create-admin` 命令行创建，之后只有超级管理员能通过接口创建 | 教程的公开 `Register` 让任何人都能给自己开一个后台账号 |
| "是否超级管理员"每次都从数据库读取，不写进令牌 | 降级或删除管理员立即生效，不用等令牌过期 |
| 管理员密码至少 12 位，用 Argon2id 哈希（`utility/password.go`，与 user 服务共用） | 教程使用双重 MD5，速度太快，可被暴力破解 |
| 文件元数据放在独立的 file 服务，而不是 gateway-admin 直连 `current` 库 | 遵守"网关不碰数据库"；以后商品、轮播图都通过 `file_id` 引用文件 |
| 存储后端做成接口，`local`（默认）和 `qiniu` 两种实现 | 没有七牛账号也能完整开发和测试；默认值永远不会把文件传到别人的空间 |
| 文件类型根据文件内容判断，只接受 JPEG、PNG、GIF、WebP，扩展名由判断出的类型决定 | 教程信任文件名后缀，伪装成 `.jpg` 的 HTML 或 SVG 会在存储域名下执行脚本 |
| 对象 key 为 `images/YYYY/MM/DD/<128 位随机数>.<ext>`；原始文件名只存进数据库用于展示 | 教程把用户提供的文件名拼进 key，存在路径和特殊字符问题；16 位随机字符串也偏短 |
| 七牛上传凭证限定单个 key、`insertOnly`、10 分钟有效，并写入大小和 MIME 限制 | 即使凭证泄露，也只能上传这一个对象 |
| 上传成功但记录失败时删除刚上传的对象，删除也失败时把 key 写进日志 | 不让存储空间堆积无人引用的孤儿文件 |
| 请求体上限由 `upload.maxImageBytes` + 1 MiB 推导，并在解析前按 `Content-Length` 拒绝 | 否则 GoFrame 解析 multipart 时会返回带内部函数名的纯文本 500 |
| 存储错误只写日志，客户端只收到 `image upload failed` | 不泄露空间名和七牛的错误细节 |

## 范围外

- 角色与权限（教程中的 `role_info`、`permission_info`、`role_permission_info`）。目前只区分"超级管理员"和"普通管理员"。
- 教程"图片关联表结构优化"一节中的 `goods_info`、`goods_images` 已在[任务 0007](0007-goods-service-and-cache.md) 实现；`rotation_info`（轮播图）、`position_info`（手工位）尚未实现。
- 删除文件、文件列表、引用计数。
- 客户端直传七牛（服务端只签发上传凭证）。现在图片会经过网关中转。
- 本地存储的多机部署：`local` 只适合单机开发。

## 七牛凭据

**不要使用教程里贴出的 AccessKey/SecretKey**：那是教程作者账号的凭据。在七牛控制台用自己的账号创建存储空间和密钥，只写进被 Git 忽略的 `config.yaml`，或使用环境变量 `QINIU_ACCESS_KEY` / `QINIU_SECRET_KEY`。七牛这条路径需要你填好凭据后自己验证一次；本仓库的自动化测试只覆盖配置校验，以及与七牛共用同一存储接口的本地实现。

## 验收标准

- 商城用户令牌、同一密钥但签发者不同的令牌、旧的 `x-user-id` 头，在 admin 和 file 服务上都返回 `Unauthenticated`；file 服务没有公开方法。
- 普通管理员、已删除的超级管理员、不存在的调用者都无法创建管理员；同名、弱密码被拒绝；错误密码和不存在的账号返回同一个错误。
- 上传：伪装成 `.jpg` 的 HTML、SVG、纯文本、空文件、超过上限的文件都被拒绝，且不会写入存储；恰好等于上限的文件可以上传；扩展名由文件内容决定；1000 次上传不产生重复 key；文件名中的路径和控制字符被清理。
- 本地存储：不覆盖已有对象；拒绝逃出存储目录的 key；目录在启动时创建。
- 记录元数据失败时，已上传的对象被删除。
- 本地端到端：管理员登录 → 上传 → 通过返回的 URL 取回完全相同的字节 → 查询文件信息；日志中没有令牌和密码。
- `gf gen ctrl`、`gf gen pb` 重新生成后没有差异；`go test ./...`、`go vet ./...`、`go mod verify` 通过，GoFrame 仍为 v2.10.2。
