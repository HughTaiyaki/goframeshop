# 任务 0018：售后审批与按商品退款

状态：已完成。开发说明见 [`docs/development/order-service.md`](../docs/development/order-service.md#6-售后) 和 [`docs/development/payment.md`](../docs/development/payment.md#11-部分退款)。这是交易闭环的最后一步：顾客对已付款订单里的某件商品申请售后，后台同意后把这件商品的钱退回去，或者拒绝并写明原因。任务 0010 只做了"申请"，0012 只有系统自动发起的整单技术退款。

## 新增了什么

| 类别 | 内容 |
| --- | --- |
| 售后状态 | `PENDING ──后台同意──▶ APPROVED ──退款成功──▶ REFUNDED`；`PENDING ──后台拒绝──▶ REJECTED` |
| 建表 | `017_after_sale_refunds.sql`：`orders.refund_info` 增加 `amount_cents`、`review_note`、`reviewed_at`、`refunded_at`、`attempts`（已有申请按订单商品回填金额）；`paysim.refund` 去掉"一笔付款只能退一次"的唯一键 |
| order 服务 | `ApproveRefund`、`RejectRefund`（只接受管理员）；恢复任务重试没退成功的售后退款；售后信息新增金额、商品名、审批意见、审批时间、退款时间 |
| 支付模拟器 | 支持**部分退款**：一笔付款可以退多次，合计不超过付款金额；全部退完才变成 `REFUNDED` |
| 后台 HTTP | `POST /backend/refund/approve`、`POST /backend/refund/reject` |
| 配置 | `order.afterSaleWindow`：订单完成后多久内还能申请售后，默认 `168h`（7 天） |

## 规则

- **申请**（在原有规则上）：
  - 订单是 `PAID`、`SHIPPED`，或 `COMPLETED` 且完成不超过 `afterSaleWindow`。
  - 金额 = 这件商品在订单里的小计（`order_goods.subtotal_cents`），申请时就记下，由服务端计算，不接受客户端填写。一件商品只能申请一次（已有唯一键）。
- **同意**：
  - 条件 UPDATE `WHERE status='PENDING'` 改为 `APPROVED`，记下审批意见和时间；然后在事务外调用模拟器退款。
  - 退款单号由售后单号派生（`AS<售后单号>`）：重试、恢复任务、重复点"同意"都是同一笔退款，模拟器只退一次。
  - 模拟器成功后改为 `REFUNDED`。没有结果（超时、模拟器不可用）就停在 `APPROVED`，恢复任务用同一个退款单号继续退，`attempts` 记录次数。
  - 已经 `APPROVED`、`REFUNDED` 时再同意：直接返回（幂等）；已经 `REJECTED`：返回 `FailedPrecondition`。
- **拒绝**：必须写原因（1–255 字）；条件 UPDATE `WHERE status='PENDING'`。已拒绝时再拒绝直接返回；已同意的不能再拒绝。
- **同意和拒绝同时发生**：只有一方改到行；另一方读到当前状态，按上面的规则返回。
- **和发货的关系**（任务 0017 留下的问题）：
  - 订单有待处理（`PENDING`）的售后时**不能发货**，返回 `FailedPrecondition`：顾客可能就是不想要了，先审批再发。
  - 订单里每件商品都已同意退款时也不能发货：没有东西可发了。
  - 已经发货的订单照常可以申请售后（退货退款的物流不在本任务范围）。
- **模拟器的部分退款**：同一个退款单号、同样的付款和金额再来一次，返回原来的结果；同一个单号但金额或付款不同，返回冲突；合计超过付款金额，返回参数错误。技术退款（整单）和售后退款不会落在同一笔付款上：技术退款只发生在没能变成 `PAID` 的订单上，售后只针对 `PAID` 及之后的订单。

## 已知局限

- 发货前的检查（有没有待处理的售后）和发货本身是两步：顾客恰好在同一瞬间提交申请，可能检查时还没有、发货时已经有了。后果只是"有待审批的售后时发了货"，申请照常审批、照常退款，钱不会算错。要彻底避免，需要在发货的 UPDATE 里带上对 `refund_info` 的条件并加锁，现在没有做。
- 售后退款失败会一直重试，没有退避和告警（和技术退款一样）；`attempts` 记录次数，指标那一轮会加上积压告警。

## 范围外

- 退货物流、按数量部分退款（一行商品只能整行退）、换货。
- 退款后的库存：已售出的库存不会自动回到可售（库存账本没有"退货入库"操作；需要时后台用"调整库存"）。
- 订单因为全部退款而关闭：订单状态不变，售后信息单独展示（详细设计 §6.1"页面分别展示订单与退款状态"）。
